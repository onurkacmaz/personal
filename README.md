# onurkacmaz.com

My personal site. One static page and a blog written in markdown, no
framework.

Live at [onurkacmaz.com](https://onurkacmaz.com), served from Cloudflare
Workers as a static-assets-only Worker.

## Layout

```
content/posts/   the blog: one markdown file per post
scripts/         build.mjs turns those files into pages, no dependencies
public/          everything that gets published
  index.html     the front page: markup, styles and script in one file
  404.html       not-found page
  blog/          generated by the build, not checked in
  img/           portrait, company and project logos, screenshots
wrangler.jsonc   Worker config: assets dir, custom domains, account
```

Nothing outside `public/` is published, so this README, the sources and the
config stay private to the repo.

## Writing a post

A post is one markdown file in `content/posts`:

```sh
npm run new -- "The title of the post"
```

That writes `content/posts/YYYY-MM-DD-the-title-of-the-post.md` with the front
matter filled in:

```markdown
---
title: The title of the post
description: One line, used on the index page and in link previews.
tags: [Go, PostgreSQL]
draft: true
---

The body, in ordinary markdown.
```

Every field is optional except the date, and that can come from the filename —
`2026-09-07-a-post.md` is dated `2026-09-07`, or set `date: YYYY-MM-DD`
explicitly. `draft: true` keeps a file out of the build. `slug:` overrides the
URL, which otherwise follows the filename, so a published URL never moves
because a title was reworded. `content/posts/_example-draft.md` shows all of
them at once.

Push to `main` and Cloudflare Workers Builds picks it up and deploys, so the
post is live a couple of minutes later. Nothing else is wired up: `build` also
runs as `postinstall`, so `public/blog/` exists by the time the deploy step
runs, wherever the deploy happens from. Deploying by hand works the same way:
`npm run deploy`.

The renderer covers headings, lists, quotes, tables, fenced code, images and
links. It is `scripts/markdown.mjs`, about two hundred lines, written here so
`wrangler` stays the only dependency in the repo.

## Local

```sh
npm install        # also builds the blog, via postinstall
npm run dev        # builds the blog, then serves public/ on localhost
npm run build      # just the blog, into public/blog/
```

The front page has no build step, so `public/index.html` still works straight
from disk. The blog pages need `npm run build` first, since `public/blog/` is
generated and not checked in.

## Deploy

```sh
npm run deploy     # build, then wrangler deploy
```

A push to `main` deploys on its own through Workers Builds, so this is only
for deploying without pushing.

`wrangler.jsonc` pins the Cloudflare account and both custom domains
(`onurkacmaz.com` and `www.onurkacmaz.com`), so a deploy from any machine
reproduces the same setup. The apex is canonical; `www` serves the same
page and the canonical link points at the apex.

The Worker has no `main` entry. With no script to run, requests are answered
straight from the edge, and unmatched paths fall through to `404.html`.

## Design

The blog pages are built from the same tokens as the front page — the same
type scale, spacing, borders and dark mode toggle — so they are not a separate
theme. `scripts/theme.mjs` holds the shared CSS and the top bar; `index.html`
stays hand-written and self-contained, and the two are kept in step by hand.
